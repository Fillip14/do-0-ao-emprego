## Como é feito

**Direto no terminal, com o agente** (Claude Code + superpowers). Arquitetura, spec, decisão técnica e código acontecem lá — não aqui. Este repo não decide nada sobre o produto; ele registra.

**Sem temas e sem `studie-tNN`.** O formato de estudo das Etapas 0–3 acabou junto com elas. Aqui o trabalho é fatiado pelo produto, não por assunto, e o aprendizado aparece no devlog do `reporte-aqui` — não em arquivo de exercício.

## Fase Agente — o que muda

A Trilha de IA abre aqui a sua quarta fase. O contrato dela:

**Você especifica → o agente implementa → você revisa e testa.**

O que isso exige de você, e é o ponto da fase inteira:

- **Especificar antes de mandar fazer.** Pedido vago devolve código vago; a qualidade do resultado é a qualidade da spec.
- **Revisar de verdade.** Código que entra sem você entender é dívida que aparece no code review da avaliação.
- **Documentar no README do capstone o que foi assistido e como foi validado.** Isso é exigência do cronograma e vira *diferencial* de portfólio — não é algo a esconder.

O limite que a fase Par mostrou continua valendo: entender no momento do commit não é o mesmo que saber defender depois.

## Como o registro volta pra cá

Quando um marco acontecer no `reporte-aqui` (primeiro deploy, auth funcionando, suíte verde, code review), ele entra no `README.md` da raiz — barra de progresso, tabela e diário de bordo — e nesta pasta, se merecer detalhe.
